# xmojo v0.1.0

**Released:** 2026-10-12 · **Previous:** first release in this repository

## What it does

XML for Mojo: parse into your own structs (`from_xml[T]`), write them back (`to_xml`), stream big
documents record by record (`Records`), or walk a compact tree (`parse -> Doc`). Built on
emberserde, so a struct that decodes from JSON decodes from XML too. Every gate run checks the
parser against CPython's expat on 4,030 generated, mutated and real documents. Library only,
Mojo 1.1.0, linux-64; `pixi install` and `-I src`, or the conda package from `recipe.yaml`.

## Highlights

- Structs in and out: attributes, child elements, text, `Optional`, `List`, `Dict` and unit enums,
  with `from_xml[T](to_xml(v, "r"))` giving `v` back.
- Conforming: XML 1.0 well-formedness and Namespaces in XML, including attribute namespaces,
  `xml:space`, line-end and attribute normalization; 0 disagreements with expat.
- Fast and small: 1.1 MB parsed in 15.4 ms (CPython's C ElementTree: 29.9 ms), about 100 bytes
  per element; `Records` keeps one record's tree in memory instead of the document's.
- emberserde's modifiers work (`Rename`, `RenameAll`, `Skip`, `Defaulted`, aliases,
  `DenyUnknownFields`), and an agent skill ships in `skills/xmojo/` (Claude Code plugin
  marketplace layout, `AGENTS.md` for other agents).

## Changes

First release in this repository. Public API:

- `from_xml[T](text, entities=...)`, `to_xml(value, root)`.
- `Records(text, local).next() -> Optional[String]`.
- `parse(text, entities=...) -> Doc` and the `Doc` accessors listed in README, "DOM".
- `html_entities()` for opt-in HTML named references; `XmlError` for malformed input.
- Mapping rules, XML handling and limits: README. Agent skill: `skills/xmojo/SKILL.md`.

## Known limits

- No DTDs: an internal subset is skipped, so its entities are unknown and raise.
- UTF-8 only: a declared encoding other than UTF-8 or US-ASCII raises.
- `parse` and `from_xml` take up to 2 GiB per document (Int32 offsets); `Records` can walk larger
  inputs, each record up to 2 GiB, but the input must be in memory.
- `Records` copies and parses each record on its own: 3.5 times slower than whole-document
  `from_xml` on 14-byte records.
- `to_xml`: no namespaces, no pretty-printing; enum arms with payloads and tuples are unsupported
  in both directions.
