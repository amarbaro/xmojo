## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
XML for Mojo: parse into your own structs (`from_xml[T]`), write them back (`to_xml`), stream big
documents record by record (`Records`), or walk a compact tree (`parse -> Doc`). Structs are
walked with Mojo's standard `reflection` module; no dependency beyond the standard library. Every gate run checks the
parser against CPython's expat on 4,030 generated, mutated and real documents. Library only,
Mojo 1.2.0, linux-64; `pixi install` and `-I src`, or the conda package from `recipe.yaml`.

## Highlights

- Parser fixes: a numeric character reference above U+10FFFF is an error, a DOCTYPE internal subset is skipped to its `]>`, an element with 16 or more attributes hashes its names correctly.
- Mixed content joins an element's text once, and namespace scoping no longer copies a dict per element.
- `len(doc)` works: `Doc` is `Sized`.

## Changes

### Added
- `len(doc)` is the element count.
- Standard library layout: `pyproject.toml`, `scripts/ci.sh`, a quickstart, `docs/api.md` and `docs/design.md`.
- CI, latest-release and license badges in the README.
### Changed
- Namespace scope is one scope with an undo log, not a dict copy per declaring element.
- `from_xml` raises a plain `Error`, not `DeserializationError`; the docs say so.
- The skill no longer mentions `emberserde`.
### Fixed
- A numeric character reference above U+10FFFF is an error.
- A DOCTYPE internal subset is skipped to its closing `]>`.
- Integer fields reject values outside their dtype.
- A `Dict` key that is not an XML name raises instead of writing markup.
- Mixed content joins an element's text once, at its end tag.
- Attribute names on tags with 16 or more attributes are hashed.
